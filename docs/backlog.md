# WhatGate Backlog（待增强清单）

M1–M6 的核心链路已完成（见 [architecture.md](architecture.md) 路线图）。本清单汇总后续增强项，供规划与贡献者认领。

**优先级**：`P0` 关键（安全/正确性底线）· `P1` 重要（可用性/完整性）· `P2` 改进（体验/优化）
**状态**：`todo` 待做 · `partial` 部分已有基础

## A. 安全与信任加固（项目立身之本，优先）

| 优先级 | 项 | 说明 |
|---|---|---|
| P0 | ~~**签名注册**~~ ✅ **已完成** | 节点用 libp2p 私钥签名 register/join（`internal/authn`），协调器校验公钥→PeerID 一致 + 签名有效 + 时间戳新鲜（防重放）。入群签名见下条（小网操作鉴权）。 |
| P1 | **小网操作鉴权** | `/group/join`·`/group/endorse` 目前无鉴权。应校验发起者确为该组成员/创建者，背书需组管理员。 |
| P1 | **声誉事件驱动 + 衰减 + 持久化** | 现有 `trust.Reputation` 只是存储；需定义"什么行为加/减分"（出口成功/超时/被举报…）、随时间衰减、并落盘。 |
| P1 | **ExitGuard 声誉门槛** | 出口策略加"只服务声誉≥阈值的请求方"（`Policy` 增字段 + 授权时校验）。 |
| P2 | **抗女巫 / 协调器限流** | 邀请制之外，加注册/入群频率限制、异常行为检测，防批量小号。 |

## B. 出口治理增强（ExitGuard）

| 优先级 | 项 | 说明 |
|---|---|---|
| P1 | **连接留痕持久化（可追溯审计）** | 出口侧把"谁、何时、连了什么"结构化落盘，配合邀请链做事后追责。 |
| P1 | **威胁情报域名源** | 定期拉取已知恶意域名清单并入 `BlockedDomains`，拦明显恶意流量。 |
| P2 | **带宽级限额与熔断** | 当前限并发连接数；补带宽配额 + 异常流量模式自动熔断并降请求方声誉。 |
| P2 | **按请求方限速** | 单请求方速率/连接上限，防单点滥用。 |

## C. 组网 / 协调 / 中继

| 优先级 | 项 | 说明 |
|---|---|---|
| P1 | **状态持久化** | 目录/邀请/信任图/声誉现全在内存，协调器重启即丢。接入嵌入式存储（如 SQLite/BoltDB）。 |
| P1 | **跨 NAT 真实验证** | 用两台不同网络的机器实测 DCUtR 打洞与 AutoRelay 自动预约（回环无法覆盖）。 |
| P2 | **协调器高可用 / 去中心目录** | 首版单实例；后续多实例或渐进式 DHT 目录，消除单点。 |
| P2 | **中继资源限制** | 给 Circuit Relay 加带宽/时长/预约数配额，防中继被滥用。 |

## 建议实施顺序（P0/P1）

排序原则：**先立工程护栏 → 打牢身份/信任底座（改协议的早做，避免返工）→ 依赖它的治理闭环 → 独立轨（传输/TUN）可并行 → 最外层 UI/移动端 → 收尾安全评审**。

### Phase 0 — 工程地基（成本低、护栏优先）
1. ~~**CI**~~ ✅ 已完成。
2. **交叉编译 + Releases** — 能把二进制发到真实环境，顺带解锁"跨 NAT 实测"。

### Phase 1 — 身份与信任底座（安全根基，越早越好）
3. ~~**签名注册（P0）**~~ ✅ 已完成（register/join 已验签）。
4. **小网操作鉴权** ← **下一项**。给 group/create·join·endorse 验签（复用 `internal/authn`），并校验发起者确为相关组成员/管理员。
5. **状态持久化** — 目录/邀请/信任图/声誉落盘，为 Phase 2 铺路。

### Phase 2 — 声誉与出口治理闭环（依赖 Phase 1）
6. **声誉事件驱动 + 衰减 + 持久化** — 依赖 5。
7. **ExitGuard 声誉门槛** — 依赖 6（声誉需先有意义）。
8. **连接留痕持久化（可追溯）** — 依赖 5，可与 6/7 并行。
9. **威胁情报域名源** — 独立，随时插入。

### Phase 3 — 传输与全局模式（独立轨，可与 Phase 2 并行）
10. **UDP 支持** — SOCKS5 UDP ASSOCIATE / QUIC。

### Phase 4 — 面向用户（最外层）

### 收尾
15. **安全评审** — 在 Phase 1–2 落地后，对隧道/协调协议/ExitGuard 专项审查。

**关键路径**：3 → 5 → 6 → 7（身份→持久化→声誉→出口门槛）是环环相扣的主线；Phase 3、Phase 4 是可并行的独立分支。
