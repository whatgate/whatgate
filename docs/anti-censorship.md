# 抗封锁设计（Anti-Censorship）

> 目标：让 WhatGate 在**国家级防火墙（GFW 类敌手）**面前仍能被普通用户用起来。本文件是设计与**分阶段路线图**，配套代码分轮落地。
>
> **本文件已经 Codex 独立对抗式评审（2026-07-26）**，评审结论已折入正文；末尾 §7 留有"评审纳入记录"。核心教训：**别把"可达"当成"可信"，别把"像 HTTPS"当成"抗审查"**——每一层都要能"失败时安全地拒绝"，而不只是"成功时能连"。

## 0. 敌手模型（我们在防谁）

GFW 类敌手同时具备以下手段，且可**组合、可选择性、可按目的地差异化**使用。为避免误判，逐项标注本设计**能/不能**覆盖：

| 敌手能力 | 说明 | 本设计定位 |
|---|---|---|
| IP 封锁 | 已知服务器 IP 黑洞路由 | Tier A/C 缓解（多端点 + 去中心化发现） |
| DNS 投毒/污染 | 域名解析到错误地址 | Tier A2/C2 缓解（TLS 校验 + 带外/DoH 引导），**不完全** |
| SNI/域名级过滤 | ClientHello 明文 SNI 命中黑名单即 RST | Tier A2 部分（CDN 混入），**非隐藏 SNI** |
| DPI 指纹 | 按握手结构/分帧/TLS·QUIC 指纹/ALPN/包长时序识别 | Tier A4 仅"粗筛"，真正抗性靠 Tier B2 |
| 主动探测 | 主动发探测包确认代理 | Tier B1/B2 目标，**A 层不覆盖** |
| **选择性丢包 / 注入 RST** | 不整封、只打断特定连接/握手 | 部分（多端点/重试），需红队实测 |
| **UDP/QUIC 一刀切** | 整段封 UDP | **常态边界**：QUIC/WebTransport 可能整体不可用，必须有 TCP 回退 |
| **主动中间人 (MITM)** | 冒充端点、篡改响应 | Tier A0 **响应签名**才能防（见下），请求签名不够 |
| **BGP/AS 级路由干预** | 区域性路由黑洞 | 超出单机方案，仅靠多故障域/带外引导减轻 |
| **端点/供应链接管** | 协调器、种子、维护者密钥被夺 | Tier A0/C2 密钥轮换+撤销+多签，**高风险单点** |
| 流量分析/关联 | 时序、包长分布统计识别 | 只做有限缓解，**不做完全防御** |

**不在本设计范围**：终端设备被植入、法律合规责任（由 ExitGuard/邀请可追溯处理，见 `README.md`）。

> ⚠️ 反面教训（评审 P0）：**不得**因为"上了 TLS/CDN/443"就认为覆盖了国家级封锁。每项能力必须有**可测的成功指标**（对抗测试/红队），而非笼统的"仍能使用"。

## 1. 当前暴露面（威胁建模）

| 封锁层 | 敌手手段 | WhatGate 当前暴露点 | 后果 | 缓解方向 |
|---|---|---|---|---|
| **发现（协调器）** | IP 封 / DNS 污染 / SNI 过滤 | 单一 HTTP 协调器，**默认明文**（`cmd/coordinator/main.go:112-119`）；`-coordinator` 单 URL（`internal/coordinator/client.go:19-34`） | 协调器一被封，**全体 M2 用户瞬断** | A0 响应签名 + A1 多端点 + A2 TLS/CDN + C 去中心化 |
| **发现（响应未认证）** | 主动 MITM / 恶意端点 | 仅**请求**签名（`internal/authn`）；客户端拿到的**目录/中继/出口信息本身未经签名** | 恶意端点可投喂**假目录**，把用户导向可监控/失陷出口 | **A0：目录/引导响应独立签名 + 撤销 epoch** |
| **发现（无缓存）** | 上条造成的短暂/持续不可达 | 节点侧**零持久化**（`cmd/node/main.go:564-565`），目录/中继仅存内存 TTL 60s | 协调器抖动/被封即无出口，冷启动直接失败 | A3 本地缓存（**须带签名+撤销+反回滚**） |
| **中继** | IP 封 | 中继与协调器同机、单 IP（`cmd/coordinator/main.go:70-84`），节点仅取一个静态中继 | NAT 用户失去唯一兜底 | 中继解耦 + 多中继 + 选路（**非默认把出口升级为中继**） |
| **数据面** | DPI 指纹 / 主动探测 | 裸 libp2p：TCP+Noise，随机高端口，`multistream-select` 明文分帧（`internal/node/node.go:70-98`） | 可指纹、可探测确认 | A4 端口伪装（粗筛）+ B1 PSK 准入 + B2 混淆传输 |

### 住宅出口 IP：**提高封锁成本，不是安全边界**（评审 P0 已纠正）

出口是普通用户住宅 IP，逐个封代价高、误伤大，**因此提高了 IP 级封锁的成本**。但这**不是安全边界**——出口仍可能被：流量关联、主动探测、用户举报、DHT 枚举、目录泄露后**定向**封锁，或被"只封访问高风险目的地的住宅出口流量"这种选择性手段命中。故总策略修正为：

> **把中心化/可探测的咽喉（协调器、中继、握手）的封锁成本抬高、故障域打散；把"可达"与"可信"严格分开——发现层只回答"在哪"，可信永远靠独立签名与撤销校验。**

## 2. 分阶段路线图

**评审关键修正（P0/P2）：A0 必须最先做。** A1（多端点）和 A3（缓存）都建立在"信任端点返回的目录"之上——若不先冻结**响应签名 + 身份 + 版本 + 撤销 + 缓存 schema**，首个切片会做出**不安全且不可兼容**的持久化格式，注定返工。因此新增 **Tier A0（协议地基）**，并把它列为**真正的第一刀**。

| Tier | 目标 | 项 | 状态 |
|---|---|---|---|
| **A0** | **协议地基（先冻结）** | 目录/引导响应签名对象、身份、版本、撤销 epoch、缓存 schema、密钥轮换 | 🟢 **目录响应签名已落地**（`internal/discovery`）；引导/撤销记录复用同一 schema，待 A3/C2 |
| **A** | 可达性 + 端口伪装 | A1 多端点切换 / A2 默认 TLS·CDN / A3 签名缓存 / A4 端口伪装 | 🟢 A1/A3/A4(WS 监听) 已落地；A2 服务端+告警已落地 |
| **B** | 主动探测抗性 | B1 网络密钥准入 / B2 混淆传输 | ⬜ 规划 |
| **C** | 去中心化发现 | C1 DHT/rendezvous / C2 带外签名引导清单 | ⬜ 规划（最终形态） |

> **已落地（2026-07-26，TDD，全绿）**：
> - **A0 目录响应签名**：`internal/discovery` 签名信封（`Sign`/`Verify`：域分隔类型、单调序号防回滚、过期、**公钥钉扎**）；协调器 `-signing-key`（缺则生成并持久化，打印公钥）对 `/directory` 签名并带单调序号；节点 `-coordinator-key` 钉扎后**验签 + 拒绝回滚 + 拒绝未签名**目录。
> - **A1 多端点故障切换**：`Client` 端点列表 + 记忆可达端点；仅连接级失败轮转，收到 HTTP 响应（含错误状态）即停止轮转——**区分"不可达"与"业务拒绝"**；切端点后目录仍经 A0 钉扎验签；`-coordinator` 逗号分隔多址。
> - **A3 签名本地缓存**：`-coordinator-cache`（需钉扎）把**已验签**目录原子落盘（0600）；全端点不可达时回退缓存并**再次验签 + 拒过期 + 拒回滚**；**验签失败不被缓存掩盖**（可能是 MITM，如实上抛）；用缓存时 `LastDirectoryStale()` 置位、cmd 打印告警。签名有效期改为 24h（离线硬上限，非新鲜度窗口；紧急吊销留给撤销 epoch）。
> - **A2**：协调器 TLS 服务端（F5 已具备）+ `http://`/未钉扎告警 + README 示例改 https://。
>
> - **A4 端口伪装（WS 监听）**：`internal/node.ParseListenAddrs`（逗号分隔多监听地址 + 校验，坏地址早报错）；`-listen` 支持多址，加 `/ip4/0.0.0.0/tcp/443/ws` 即让数据面骑 :443 像 web 流量（libp2p WS 传输默认已启用，已测真起 WS 监听）。**诚实边界**：这只是**粗筛级伪装非探测抗性**（真探测抗性见 Tier B）；要真正像 HTTPS 需 TLS——`/tls/ws`+证书 或 TLS 反代；多数住宅节点无公网入站/特权端口，保持**拨号-only 经中继**（不监听 :443）。默认仍 TCP/0，不默认 :443（会打断没有入站能力的节点）。
>
> 真机烟测：协调器打印公钥、`/directory` 返回签名信封、重启载入同一密钥；节点 `/ws` 监听地址真实起听。**仍未签名**：`/relay`、`/trust`、`/reputation`、`/groups` 等读端点（schema 已备，后续复用）；A2 的"默认 https + CDN 前置"、A4 的"TLS-ws/反代"仍是**部署文档级**建议（代码不强制）。**下一步**：Tier B（B1 网络密钥准入 / B2 混淆传输）或 Tier C（去中心化发现）。

### Tier A0 — 协议地基（先冻结，勿跳过）

在写任何端点轮转/缓存代码**之前**先定死这套"可验证对象"，A1/A3/C2 全部复用它：

- **签名对象与签名域**：为**目录条目 / 引导清单 / 撤销记录**分别定义独立的可签名结构（`domain` 前缀区分用途，防跨用途重放），字段含：`type`、`serial`（单调递增）、`issued_at`、`expires_at`、`revocation_epoch`、`min_acceptable_version`。
- **响应认证 ≠ 请求认证**：现有 `internal/authn` 只证明"客户端是谁"；A0 增加**服务端/控制面对响应内容的签名**，客户端**验签通过才采信**目录/中继/出口信息。
- **身份绑定**：把"出口—PeerID—多地址—中继—能力/协议版本"作为一个**原子绑定对象**签名，避免"出口还在但地址/中继/PeerID 已变"的旧组合被错误拼装。
- **撤销与反回滚**：撤销 epoch + `min_acceptable_version`，让离线/缓存路径也能识别"这条已被紧急吊销"或"版本过旧不可用"。
- **密钥轮换**：离线根密钥签在线子密钥；客户端内置可审计的轮换机制（为 C2 多签/阈值签名预留）。

**验证**：篡改签名/过期/低于版本下限的对象 → 客户端拒绝采信并**安全降级**（而非静默使用）。

### Tier A1 协调器多端点 + 故障切换
- `-coordinator` 支持逗号分隔多 URL；`Client` 从单 `baseURL` 改为**端点列表** + 健康端点记忆。
- **区分"网络不可达"与"业务拒绝"（评审 P0）**：仅前者触发轮转；后者（4xx 业务错误）**不**换端点。轮转到新端点后，**目录仍须经 A0 同一信任根验签**——绝不因"这个端点连得上"就信任其返回内容（否则对手选择性阻断健康端点即可把用户赶向恶意端点）。
- **多端点 ≠ 独立（评审 P0）**：端点清单须带**故障域元数据**（ASN / DNS 托管商 / CDN / 证书密钥 / 运维主体），并要求跨故障域分散；"独立性"列为上线验收项。
- **幂等/重试语义（评审 P1）**：写类请求（register/report/join）标注请求 ID + 截止时间 + 幂等规则，failover 重发不得造成重复注册/状态分裂/签名时间窗失效；读类才可自由 failover。
- **健康记忆（评审 P1）**：带网络上下文（换 Wi-Fi/蜂窝即重置）、指数退避、半开探测；单次失败不永久降权。
- 内置一小份**种子端点**（编译进二进制，**是冷启动下限，非长期依赖**；旧版本 seed 全失效需靠 C2 自愈）。

### Tier A2 默认 TLS / CDN 前置
- 默认 `https://`；`-tls-cert`/`-tls-key` 已实现（`cmd/coordinator/main.go:37-38,112-119`），本项是**默认化 + 部署文档**。
- CDN 前置：置于 CDN 后、:443、SNI 用普通业务域名，靠"混入海量正常 HTTPS 的**附带损害成本**"，**不是**隐藏真实 SNI（域名前置已被主流 CDN 封堵）。
- **评审 P0 纠正**：CDN 前置**不等于**"与正常 HTTPS 不可区分"——SNI、证书链、HTTP 路径、请求大小/节奏、长连接行为、边缘→源站拓扑都是分类特征；CDN 也可能按域名/客户/政策配合封禁。**故 CDN 定位为"可用性冗余层"，不是不可观测层**；成功判据是**真实受限网络的对抗分类测试**，不是"抓到 TLS 包"。

### Tier A3 节点侧**签名**本地缓存
落盘上次可用的目录/中继/peer，协调器不可达时续命。**但必须（评审 P0）**：
- **按对象独立签名/版本/TTL**（复用 A0），**禁止未验签数据参与拨号**；不做"整块目录快照"（会拼出失效组合）。
- **不绕过撤销**：缓存条目带撤销 epoch + `min_acceptable_version` + 硬失效时间；定义**离线模式最大风险窗口**，超窗硬失效。24h TTL 只是"最后手段"上限，**不能表达紧急撤销**——紧急撤销靠 epoch。
- **本地取证资产最小化**：缓存含住宅 IP/PeerID/多地址/关系，是高价值本地资产 → 用户专属权限 + 可选静态加密 + 最小化保存 + 反回滚（防本地恶意进程篡改/回滚）。
- **调用方可见状态（评审 P2）**：普通 SOCKS 客户端看不到日志/UI 提示，"过期仍用"等于**静默安全降级** → 给调用方明确状态码/健康状态 + 可配置离线风险策略。
- **首次引导单列（评审 P1）**：缓存只救"曾成功过"的设备；首次安装/换设备/清缓存/长期离线/全量轮换后**无缓存可用** → 首次引导（种子 + C2 带外）是**独立核心场景**，不能靠缓存。

### Tier A4 数据面端口伪装
- 现默认仅 TCP 随机口（`internal/node/node.go:75-77`）。目标：让数据连接形似普通 HTTPS，消除"随机高端口 + 高熵流量"这一最廉价特征。
- **评审 P0 纠正三点**：
  1. **WSS 与 WebTransport 是两条不同的路**：WSS 走 TCP/TLS + HTTP Upgrade + 证书/域名语义；WebTransport 依赖 **HTTP/3 = QUIC = UDP**，而**许多受限网络整段封 UDP** → **UDP 被封是常态边界**，QUIC 路径必须有 TCP/WSS 回退。二者分别设计，勿混为"默认监听 :443"。
  2. **:443 不是免费资源**：与真实网站/反代/证书续期/宿主服务冲突；且**多数住宅节点没有特权端口、入站映射或公网 IPv4** → 它们**只能做拨号方/经中继**，不是 :443 监听方。需定义单 IP/单端口复用（SNI/ALPN 路由）+ 证书责任边界 + 无公网入站时强制走中继。
  3. **"抓包像 HTTPS" ≠ 抗 DPI**：TLS/QUIC 指纹、ALPN、扩展顺序、证书、首包、连接生命周期、包长时序仍可稳定区分。A4 只是**粗筛级伪装**，真正探测抗性在 B2。成功判据=目标网络实测分类对抗，非目视抓包。

### Tier B — 主动探测抗性（GFW 级）

#### B1 网络密钥准入（libp2p `pnet`）
- 让全网成为一个 libp2p **private network**：未持网络密钥者握手第一步就失败（反主动探测 + 天然挡陌生人）。
- **评审 P0 纠正——密钥派生方式**：**不得**用邀请码/小网口令直接派生全网 PSK（低熵秘密放在准入边界；泄露影响整网；轮换全员断连；无法撤销单成员）。改为：**高熵随机网络密钥**作短期保护层 + **成员级凭据**分发/封装/撤销；邀请码只用于**取得**成员凭据，不等价于网络密钥。与安全评审 F5（口令改 HMAC 挑战）统一设计。
- **评审 P0 纠正——pnet/QUIC 兼容性别写死**：旧资料称"pnet 仅 TCP 不支持 QUIC"**可能已过时**——现行 go-libp2p QUIC transport 构造接口已接收 `pnet.PSK`。**落地前必须锁定 go-libp2p 版本**，对 TCP/WSS/QUIC/WebTransport 各写"无 PSK / 错 PSK / 正确 PSK"的**互操作 + 抓包测试矩阵**，据实测决定各传输取舍，**不得基于旧资料禁用或保留传输**。
- **评审 P0——PSK ≠ 无指纹响应**：即使 pnet 覆盖某传输，连接超时/关闭时机/TLS·QUIC alert/包长/重传/端口行为仍可构成主动探测预言机。**B1 只是准入层，不是完成的探测抗性**；以黑盒主动探测 + 统计分类验证，而非只验"正常能连、错 PSK 不能连"。

#### B2 可插拔混淆传输
- 为流套抗主动探测的握手。候选：**obfs4 类**（PSK 认证 + 随机化）、**TLS 拟态/REALITY 风格**（对真实前置域完成真 TLS 再复用）。
- **评审 P0 纠正**：obfs4 与 REALITY **协议边界差异大**（握手/密钥分发/真实站点/TLS·QUIC/反代/连接复用/错误语义各不同），**不能保证在 libp2p transport option 处简单套层**。故先产**可行性原型 + 分层图**，按每条路径的安全性质/部署依赖/故障模式/退出条件选型，**不先承诺统一插件接口**。定位：军备竞赛项、后置可选，视封锁实况投入。

### Tier C — 去中心化发现

#### C1 DHT / rendezvous
- 引入 libp2p Kademlia DHT + rendezvous 作为协调器替代/补充。**评审 P0 纠正若干误判**：
  - **不是"没有单点可封"**：DHT 的 bootstrap、路由表、relay、NAT 穿透仍构成**少数高价值节点**；CGNAT/大规模 NAT 下更糟。诚实定位为**"多点控制面"**，先做"协调器 + DHT 双轨"。**先定义无协调器时完整的冷启动 + NAT 可达路径**。
  - **rendezvous 是服务端发现，不天然去中心化**：其注册表是成员在线/角色的集中情报源，单列其信任/可用性/日志留存/抗枚举/多运营者模型，勿与 DHT 混称。
  - **"发现≠信任"要落成可执行模型**：对手可发布伪出口、替换地址、重放旧记录、占据近邻键空间、eclipse。故 **DHT 只承载"已认证记录"的索引，绝不作授权来源**；出口广告须带 A0 的可验证身份/授权链/能力声明/短期签名/序列号/撤销/资源限额。
  - **Sybil（评审 P0）**：邀请制/PSK 不解决女巫——一个泄露邀请码/被攻陷成员即可批量造身份；共享 PSK 还使成员无法归因/撤销。需**每成员独立凭据 + 可撤销授权 + Sybil 成本**；对路由表/provider 记录/rendezvous 注册/拨号并发做配额+挑战+异常检测。
  - **枚举面（评审 P0）**：DHT/rendezvous 放大成员与出口枚举（PeerID/地址/在线/角色/关联）；私有 DHT 在密钥泄露后整体暴露。→ 角色发现分区、最小化广告字段、短期身份/地址、限查询范围与速率；"成员/出口可枚举性"列为独立隐私验收项。

#### C2 带外签名引导清单
- 从难封渠道（CDN 静态 JSON / GitHub raw / DoH TXT）拉签名的引导清单（协调器/中继/DHT bootstrap 地址），内置公钥验签防投毒。协调器或 DHT 种子被封后**自我修复**（类 Tor bridges/moat）。
- **评审 P1 纠正**：
  - **签名只解决真实性，不解决可达性/回滚/选择性审查**：各渠道共享公开 DNS/域名/TLS/平台可用性，可被封/污染/限流/返回陈旧/按地域差异化投放 → **每渠道独立建模故障域**，并在真实受限网络验证。
  - **反回滚 + 防分裂视图**：对手可给不同用户投放"签名有效但陈旧/不同"的清单以长期隔离或诱导连向失陷节点 → 清单加**单调版本 + 最短接受版本 + 有效期 + 透明日志/见证 + 跨源一致性**。
  - **维护者单公钥是高价值单点**：泄露可全网投毒、丢失可永久失去更新 → **离线根 + 在线子密钥 + 阈值/多签 + 客户端内置可审计轮换**。

## 3. 首个落地切片（下一轮 TDD）：**A0 + A2**（而非原 A1+A3）

评审后调整：**先冻结协议地基 A0 + 默认 TLS A2**，因为 A1/A3 在 A0（签名目录 + 缓存 schema + 撤销）就位前落地会返工且不安全。A1/A3 紧随其后、复用 A0。

## 4. 验证方式（对手驱动，非仅功能通路）

评审 P1：**每 Tier 必须定义"失败时安全地拒绝"，加入自动化故障注入/红队**，不只验"成功能连"。

- **A0**：目录投毒/签名篡改/回滚/低版本 → 客户端拒绝并降级。
- **A1**：封掉第一个协调器→自动切次端点；**注意**——只验"**新连接**恢复时间"，**不承诺既有连接不中断**（协调器切换只影响后续发现；已有 SOCKS/TCP 流不能跨出口/中继/会话迁移，出口变更还会换源 IP 打断登录/TLS 会话）。需实现出口黏滞 + 会话耗尽 + 客户端可见降级语义。
- **A2**：CDN 后抓包确认 :443 TLS + 普通 SNI；并做真实受限网络分类对抗（非仅抓包）。
- **A3**：填充缓存→停协调器→重启，仍能用**验签通过**的缓存出口出网（`curl --socks5-hostname 127.0.0.1:1080 https://api.ipify.org`）；篡改/撤销缓存→拒绝。
- **A4**：分别验 TCP/WSS 与 QUIC/WebTransport；**把 UDP 被封设为常态**测例；分类对抗而非目视。
- **B1**：无 PSK/错 PSK 探测→无可用响应且**无可指纹侧信道**；正常成员连通。
- **B2**：已知代理指纹工具 + 主动探测脚本→不被识别。
- **C1**：断协调器仅经 DHT 发现连通；并验 Sybil 灌入/eclipse/枚举/伪出口→被拒或受限。
- **C2**：篡改/回滚/分裂视图清单→拒绝；合法清单→切换。
- **横切**：目录投毒、缓存回滚、DHT eclipse、Sybil、选择性阻断、错误 PSK 探测、UDP 被封、CDN/证书故障、relay 耗尽——纳入红队验收。

## 5. 横切关注点（评审新增）

- **恶意出口（P1）**：发现层签名只证"被授权"，不证"可信/未被接管"。恶意出口可观察目的地址/DNS/元数据、篡改明文 HTTP → 明确**出口信任等级 + 用户提示**，默认鼓励**端到端 TLS/DNS 隐私**，建立出口撤销/信誉/异常处置。
- **中继治理（P1）**：中继解耦后仍是源/目的关联点与限速/封锁/滥用集中点；**不默认把普通出口升级为中继**——单独定义中继准入/带宽·并发·时长限额/审计最小化/角色授权/健康探测/运营责任；多中继需带故障域约束的选路 + 黏滞 + 退避 + 熔断。
- **资源治理（P1）**：DHT 查询/rendezvous 注册/relay 转发/主动探测/缓存刷新都可被放大为 CPU/连接/带宽/磁盘耗尽 → 全链路速率限制 + 消息/流大小上限 + **认证前成本控制** + 缓存配额 + 可观测拒绝策略。

## 6. 与既有工作的关系

- **安全评审 F5**（口令 HMAC 挑战、协调器 TLS）与 **A2 / B1** 同源，统一设计。
- **ExitGuard / 邀请可追溯**（`internal/exit`）处理**滥用与合规**——与抗封锁**大体正交但非完全**（评审 P2）：可追溯身份、集中邀请关系、审计日志会**增加成员图谱/出口角色/关联的暴露面**，需对二者数据流/日志留存/身份绑定/泄露后果做**联合隐私评审**。
- **凭据卫生 F8**（remote URL 内嵌 PAT）：同属"别把秘密暴露"，尽快轮换。

## 7. 评审纳入记录（Codex, 2026-07-26）

Codex 只读对抗评审提出 **23×P0 / 11×P1 / 3×P2**，**几乎全部采纳**，主要结构性改动：
- **新增 Tier A0 协议地基**并前置为第一刀（原 A1+A3 → 改为 A0+A2 先行）——因为"响应未认证"是最大架构缺口（请求签名≠响应签名）。
- **纠正事实性表述**：`pnet` 对 QUIC 的支持别写死（要版本锁定 + 测试矩阵）；"代理不中断"改为"新连接恢复时间"（既有流不可迁移）；:443 对住宅节点**不免费**（多为拨号/中继方）；WSS≠WebTransport 且 UDP 被封是常态。
- **纠正安全误判**：住宅 IP 是**成本项非安全边界**；CDN 是**可用性冗余非不可观测**；邀请码**不得**直接当全网 PSK；DHT**不是**"消除单点"而是"多点控制面"；"发现≠信任"要落成可执行的签名/撤销模型。
- **补齐缺失面**：撤销 epoch / 反回滚 / 缓存投毒与本地取证 / Sybil 与枚举 / 恶意出口 / 中继治理 / 资源治理 / 首次引导独立场景 / 对手驱动红队验证 / 维护者密钥轮换与多签。
- **未在本轮细化（承认为后续专项，非驳回）**：阈值/多签的具体门限与见证机制、完整资源治理配额、B2 可行性原型、pnet 测试矩阵的实测结论——均在各自 Tier 落地前先出专项结论。
